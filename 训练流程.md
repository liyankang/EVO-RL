# Keyboard HIL 改动说明

## 背景

原项目的人在环路流程，默认是：

- `policy` 控制从臂执行
- `leader arm teleop` 作为人工接管来源
- 训练/录制中通过键盘只负责切换干涉状态、标记成功/失败

现在改成：

- `policy` 仍然控制从臂执行
- 人工接管来源从 `piperx_leader / piper_leader` 改为 `keyboard_piper_tcp`
- 训练中途可以直接用键盘干涉从臂，不再依赖主臂硬件

你之前用于验证主从链路的命令是：

```bash
lerobot-teleoperate \
  --robot.type=piperx_follower \
  --robot.port=<FOLLOWER_CAN_PORT> \
  --robot.id=my_piperx_follower \
  --robot.require_calibration=false \
  --teleop.type=piperx_leader \
  --teleop.port=<LEADER_CAN_PORT> \
  --teleop.id=my_piperx_leader \
  --teleop.require_calibration=false
```

现在目标是把 `--teleop.type` 替换成键盘控制。

## 参考逻辑来源

键盘控制的主要参考代码来自：

- `tests/my_test/keyboard_tcp_control.py`

这个文件里原本实现了：

- Piper 从臂启动后先移动到固定初始关节角
- 通过 FK 得到当前 TCP
- 键盘按键控制 TCP 的位置增量
- 用 IK / 差分控制把 TCP 目标转成关节命令下发给从臂

## 本次实际改动

### 1. `src/lerobot/scripts/lerobot_teleoperate.py`

改动内容：

- 将 `keyboard_piper_tcp -> piper_follower` 的适配扩展到 `piperx_follower`
- 让 `keyboard_piper_tcp` 在 `piper_follower` 和 `piperx_follower` 上都能：
  - 自动启用 Piper TCP 的 IK action processor
  - 启动时从当前机器人姿态同步初始 TCP 目标

效果：

- 现在 `lerobot-teleoperate` 不只支持 leader 控制
- 也支持直接用键盘控制 `piper_follower / piperx_follower`

### 2. `src/lerobot/scripts/lerobot_record.py`

改动内容：

- 把 `teleoperate` 里已有的 `keyboard_piper_tcp` 配对逻辑复用到 `record`
- 当 `teleop.type=keyboard_piper_tcp` 时，录制链路会自动使用对应的 IK processor
- 机器人连接后，会先把键盘 teleop 的内部 TCP 目标同步到当前从臂姿态
- 数据集 action schema 改为根据 `robot_action_processor` 构建，而不是继续按原始 teleop 输入直接建

效果：

- `record / human_inloop_record` 里键盘 TCP 控制链路正式可用
- 数据集里保存的 action 字段能和真实发送给从臂的动作保持一致

### 3. `src/lerobot/scripts/recording_loop.py`

改动内容：

- 录制数据时，`action` 从原来的 `action_values` 改为 `robot_action_to_send`

效果：

- 对 `keyboard_piper_tcp` 这种“先给 TCP，再经 IK 转关节”的控制方式，数据集保存的是最终真正下发到机器人上的动作
- 这对后续训练更合理，也更符合“键盘干涉从臂”的真实执行语义

### 5. `src/lerobot/robots/piper_follower/robot_kinematic_processor.py`

改动内容：

- 将 `tests/my_test/keyboard_tcp_control.py` 里的微分 IK 思路接入正式 `PiperInverseKinematicsEEToJoints`
- 新增数值位置雅可比与 DLS 求解
- 正式 `keyboard_piper_tcp` 链路统一只走微分位置 IK
- 原来的完整姿态 IK 回退逻辑已取消

效果：

- 更贴近原测试脚本的键盘控制手感
- 更适合训练中途的小步人工干涉
- 行为更稳定、更容易预期

### 4. 测试文件

改动了：

- `tests/test_piper_teleop.py`
- `tests/test_control_robot.py`

补充内容：

- 增加 `keyboard_piper_tcp` 与 `piperx_follower` 的适配测试
- 增加 `record` 链路中对键盘 Piper TCP 配置的调用测试

### 5. `Piper_mujoco/piper_mujoco_sim.py`

改动内容：
- 把原来 `--mode ik` 里写死的固定 target 改成真正的键盘 TCP 控制模式
- 启动时从当前机械臂末端位姿读取初始 TCP，而不是继续用硬编码目标点
- 保持初始姿态四元数不变，只通过键盘修改 TCP 位置目标
- 目标位置更新后，持续交给 `CartesianIKController` 跟踪

配套改动：
- `Piper_mujoco/renderers.py`
  - 增加 viewer 键盘事件缓存，供 `piper_mujoco_sim.py` 消费按键
- `Piper_mujoco/README.md`
  - 补充 `--mode ik` 的按键、步长和用途说明

当前 `Piper_mujoco --mode ik` 键位：
- `W/S`：`+/- X`
- `A/D`：`+/- Y`
- `Q/E`：`+/- Z`
- `+` / `=`：增大步长
- `-`：减小步长
- `Space`：暂停 / 继续 viewer
- `Esc`：退出

当前默认步长：
- `0.01 m`
- 缩放倍率 `1.5x`

效果：
- 现在 `python Piper_mujoco/piper_mujoco_sim.py --mode ik` 才是真正可用来测试键盘 TCP 控制的仿真入口
- 不再是之前那个只会一直追踪固定 target 的演示模式

额外补充：
- 现在 `Piper_mujoco/piper_mujoco_sim.py` 还支持通过 UDP 接收外部 6D 末端位姿
- 适合把手机姿态、IMU、或者其他 teleop 脚本的输出直接送进 MuJoCo 仿真
- 支持两种单位格式：
  - `piper`
    - 位置按 `EndPoseCtrl` 风格整数输入
    - 姿态按 `0.001 deg`
  - `si`
    - 位置按米
    - 姿态按弧度

## 现在建议的使用方式

### 1. 键盘直接控制从臂联调

可以把原来的 leader 配置改成：

```bash
lerobot-teleoperate \
  --robot.type=piperx_follower \
  --robot.port=<FOLLOWER_CAN_PORT> \
  --robot.id=my_piperx_follower \
  --robot.require_calibration=false \
  --teleop.type=keyboard_piper_tcp
```

如果你控制的是 `piper_follower`，同理把 `robot.type` 换成对应型号即可。

### 2. 人在环路录制 / 训练介入

当前仓库对应的 HIL 入口是：

```bash
lerobot-human-inloop-record
```

键盘介入版的大致命令形态应改成：

```bash
lerobot-human-inloop-record \
  --robot.type=piperx_follower \
  --robot.port=<FOLLOWER_CAN_PORT> \
  --robot.id=my_piperx_follower \
  --robot.require_calibration=false \
  --teleop.type=keyboard_piper_tcp \
  --dataset.repo_id=<HF_USER>/<DATASET_NAME> \
  --dataset.single_task="<YOUR_TASK>" \
  --dataset.num_episodes=<N> \
  --policy.path=<YOUR_POLICY_PATH>

  lerobot-human-inloop-record \
  --robot.type=piperx_follower \
  --robot.port=can0 \
  --robot.id=my_piperx_follower \
  --robot.require_calibration=false \
  --teleop.type=keyboard_piper_tcp \
  --dataset.repo_id=local/push_button \
  --dataset.root=/home/user/.cache/huggingface/lerobot/lerobot_v3/data_toiletButton_0609 \
  --dataset.single_task="press the toilet button" \
  --dataset.num_episodes=10 \
  --dataset.episode_time_s=15 \
  --dataset.reset_time_s=5
```

如果你只是先测试“键盘能不能中途接管”，最关键的是这几项：

- `--teleop.type=keyboard_piper_tcp`
- `--robot.type=piperx_follower` 或 `piper_follower`
- `--policy.path=...` 存在时，HIL 状态机才会开启

默认热键逻辑仍然是：

- `i`：切换是否进入人工干涉
- `s`：标记成功并结束当前 episode
- `f`：标记失败并结束当前 episode

目标模式变成：

- policy 正常跑
- 键盘作为人工干涉输入源
- 中途切换 intervention 后，由键盘控制从臂

也就是说，后续 `human_inloop_record` / `record` 的 teleop 配置，应优先换成：

- `--teleop.type=keyboard_piper_tcp`

而不是继续使用：

- `--teleop.type=piper_leader`
- `--teleop.type=piperx_leader`

## 当前已知说明

- 当前键盘 TCP 控制的正式接入，主要是复用了仓库里已有的 `keyboard_piper_tcp` 逻辑，并把它补通到 `teleoperate + record + HIL` 链路
- 当前正式 `keyboard_piper_tcp` 的 IK 行为已经调整为：
  - 统一走微分位置 IK
- 你提到的 `tests/my_test/keyboard_tcp_control.py` 更像是实验/原型脚本；这次改动的目标不是直接拿这个测试脚本去跑训练，而是把同类能力接进正式框架
- 对键盘 teleop，HIL 入口里默认不再启用 `policy -> teleop` 的动作镜像，因为键盘本身不需要 leader 那种反馈同步

## 最小验证

仓库里新增了一个不依赖 `pytest` 的最小验证脚本：

- `tests/my_test/validate_keyboard_piper_tcp_pipeline.py`

用途：

- 验证 `KeyboardPiperTCPTeleop` 能产出正式 `ee.*` 动作
- 验证正式 `PiperInverseKinematicsEEToJoints` 能接收这类动作
- 验证纯位置更新时会优先走微分 IK 分支

运行方式（PowerShell）：

```powershell
$env:PYTHONPATH='src'
.\.venv310\Scripts\python.exe tests/my_test/validate_keyboard_piper_tcp_pipeline.py
```

预期输出：


动作跳变方法解决思路：

方法 1：减小 chunk 长度（让模型更容易学平滑）
--policy.chunk_size=10 \
--policy.n_action_steps=10 \
这样每 10 帧就重新推理一次，跳变更频繁但幅度更小。方法 2：开启 RTC（Real-Time Chunking）RTC 会在每帧都利用最新观测来修正 action chunk，减少边界跳变：
--policy.rtc_config.enabled=true \
方法 3：增加训练步数 / 降低 LoRA rank
--steps=50000 \       # 多训一些
--peft.r=8 \          # 降低 rank 防过拟合
